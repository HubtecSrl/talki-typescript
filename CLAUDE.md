# talki-typescript

The TypeScript SDK for Talki's public API, published to npm as `@hubtec/talki`.
MIT. This repo will be public: write every file, commit message and PR for an
outside reader. No internal hostnames, people, PR numbers of private repos, or
customer names.

It mirrors the Python SDK (`talki-python`, PyPI `talki`), which is the
reference for behaviour: the retry and idempotency rules, the OAuth renewal
(rotation, the 60 s grace re-present, the single lock, the refused-forever
states), the error classes, paging and webhook checks. A change to one of
those belongs in both SDKs.

## Where things come from

- `openapi/talki-v1.yaml` is a pinned copy of the spec that `talki-backend`
  exports and commits at `api-cli/openapi/talki-v1.yaml`. Refresh it with
  `node scripts/pull-spec.mjs`, which reads the sibling backend checkout's
  `origin/main`, what production serves (or pass a path or URL). Never release
  from a `--ref origin/dev` pull. A wrong or missing schema is fixed in the
  backend, never here: never hand-edit the YAML.
- `src/generated/` is generated by `npm run generate` (`scripts/generate.mjs`)
  and never edited by hand. CI fails on drift (`npm run generate:check`).
  - `schema.ts`: openapi-typescript (pinned, exact, in `package.json`) over the
    spec, with `defaultNonNullable: false` and one transform: a string with
    `x-extensible-enum`, or an enum whose description says new values may be
    added, becomes its values `| (string & {})`.
  - `models.ts`: an alias per schema. A schema named like a hand-written export
    fails the generator (`RESERVED`).
  - `resources.ts`: the resource classes, their `withRawResponse` twins, the
    `Resources` base `Talki` extends, `OPERATIONS` (what each method sends) and
    `SURFACE`.
  - `api-version.ts`: `API_VERSION`, the spec's `info.version`.
- Everything else in `src/` is hand-written: `client.ts` (`Talki`), `core.ts`
  (building requests, reading answers), `transport.ts` (retries, idempotency
  keys, timeouts), `errors.ts`, `oauth.ts`, `pagination.ts`, `webhooks.ts`,
  `logging.ts`, `version.ts`, `index.ts`.
- The method names are derived from the operation IDs (operation less the
  tag's noun; both keep their full names when two would collide), so a new
  operation can rename an existing method. `test/resources.test.ts` pins the
  whole surface in `METHODS`, the same map as the Python SDK's, camelCased: a
  change there is a breaking change and needs a changelog line.
- A new header parameter in the spec needs an option name in `HEADER_OPTIONS`
  in the generator, which fails until it has one.

## Checks

```sh
npm ci
npm run lint            # Biome; src/generated is excluded
npm run typecheck       # strict, src and test
npm test                # vitest, against a mocked fetch
npm run generate:check
npm run build && npm run smoke   # dist/esm and dist/cjs, loaded through the exports map
```

CI (`.github/workflows/ci.yml`) runs these on Node 20, 22 and 24, then loads
the build on Bun and Deno, on GitHub-hosted runners only. This repo takes fork
PRs, so it must never use self-hosted runners. Cloudflare Workers is a target
but not tested in CI: keep `src/` free of `node:` imports and Node globals
(`process` is read only through `globalThis`, guarded).

## Releasing

1. Move the `CHANGELOG.md` entry from "Unreleased" to the version, bump
   `version` in `package.json` and `VERSION` in `src/version.ts` (a test checks
   they match), and merge.
2. Tag `v<version>` on `main` and push the tag. `release.yml` checks that the
   tag matches and is on `main`, runs every check, builds, and publishes by npm
   trusted publishing (OIDC, the `npm` environment; no token is stored). A
   version with a `-` (`0.1.0-beta.1`) goes out under the `beta` dist-tag, any
   other under `latest`. Trusted publishing cannot move dist-tags afterwards, so
   while only prereleases exist `latest` stays on the first one, and a plain
   `npm install @hubtec/talki` gets it. To make a prerelease the default, the
   maintainer runs `npm dist-tag add @hubtec/talki@<version> latest` by hand.

`0.1.0-beta.1` was published by hand to create the package; from `0.1.0-beta.2`
on, every release goes through `release.yml`.

The package uses semver of its own. `API_VERSION` (the spec's dated version) is
what it sends as `Talki-Version` by default. Moving to a newer API version is a
changelog line, and a major bump if it breaks callers.

## Working rules

- `main` is the only branch. Work on a feature branch and open a PR into `main`.
  Merge only when the maintainer says so, and never push a release tag without
  asking.
- Run a code-review agent before every push, fix, re-test.
- Commit only your own paths (`git commit -- <paths>`).
- Zero runtime dependencies: anything new goes in `devDependencies`, pinned
  exactly.
